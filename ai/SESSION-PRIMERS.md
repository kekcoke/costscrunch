## backend · `feat/backend/fix-critical`

```
You are the backend-agent for this worktree (feat/backend/fix-critical).

Start by reading these files:
1. .agent.md — your full domain context and issue list
2. backend/src/lambdas/auth/index.ts
3. backend/src/lambdas/groups/index.ts
4. backend/src/lambdas/analytics/index.ts

Your 6 issues, in fix order:

DEP-004 (SECURITY CRITICAL) — auth/index.ts, DELETE /auth/account handler
  The handler reads userId from the request body. An authenticated user can delete any
  account by passing another user's ID. Fix: replace body read with getAuth(event).userId.
  Never read identity from request body in any handler.

CON-001 (CRITICAL) — groups/index.ts, join handler
  Read-check-write pattern on group membership is a TOCTOU race. Two concurrent joins can
  both pass the duplicate check. Fix: replace with PutCommand + ConditionExpression
  'attribute_not_exists(pk) AND attribute_not_exists(sk)'. Return HTTP 409 on
  ConditionalCheckFailedException.

CON-002 (HIGH) — groups/index.ts, settlement handler
  Promise.all over multiple DynamoDB writes is non-atomic. Fix: replace with a single
  TransactWriteCommand. Guard: if settlement produces >100 items, return HTTP 422.

DEP-002 (HIGH) — search all Lambda handlers
  A debug route that intentionally throws 500 ships in production. Find it and delete it
  entirely — no env check, no feature flag.

PERF-001 (HIGH) — analytics/index.ts
  QueryCommand result is not paginated — data is silently truncated at 1MB.
  Fix: loop with ExclusiveStartKey until LastEvaluatedKey is undefined.

DEP-001 (HIGH) — expenses/index.ts reads process.env.BUCKET_ASSETS_NAME
  This env var is injected by infra-agent (IaC-004). Before fixing this side, confirm
  infra PR has merged: git fetch origin && git log origin/main --oneline | grep IaC-004
  Once confirmed: verify the handler reads the var correctly and add it to .env.test.

Work one issue at a time. After each fix run: cd backend && npm run test:ut
For CON-001 and CON-002 fixes, also run integration tests (LocalStack required —
use the lock guard from localstack-agent §9, do not call docker compose up -d directly).
Open a PR when all committed fixes are green. Update ai/WORKTREES.md row to 'pr open'.
```

```
Your 6 issues, deploy blockers first:

IaC-001 (CRITICAL) — expense-export Lambda completely absent from the CDK stack
  backend/src/lambdas/expense-export/index.ts exists but is never deployed.
  Add a NodejsFunction following the same pattern as existing Lambdas:
  - Grant table.grantReadData + assetsBucket.grantPut
  - Add BUCKET_ASSETS_NAME to its environment (part of IaC-004 below)
  - Register GET /expenses/export with the JWT authorizer
  Mirror to bootstrap.sh env injection block and SAM template.

IaC-003 (CRITICAL) — Redis security group has no inbound rules
  All Lambda→Redis connections time out. Fix: add an ingress rule on the Redis SG
  allowing TCP 6379 from the Lambda security group.
  redisSecurityGroup.addIngressRule(lambdaSecurityGroup, ec2.Port.tcp(6379), '...')

IaC-005 (CRITICAL) — Cognito post-confirmation trigger missing Lambda permission
  auth-trigger Lambda is set as the trigger but the resource policy granting Cognito
  lambda:InvokeFunction is missing. New user registration is broken in prod.
  Fix: authTriggerFn.addPermission('CognitoInvoke', { principal: new
  iam.ServicePrincipal('cognito-idp.amazonaws.com'), sourceArn: userPool.userPoolArn,
  action: 'lambda:InvokeFunction' }). Verify userPool.addTrigger() is not bypassed.

IaC-004 (HIGH) — BUCKET_ASSETS_NAME never injected into Lambda environments
  expenses Lambda and expense-export Lambda both read process.env.BUCKET_ASSETS_NAME
  but the CDK stack omits it. Fix: add BUCKET_ASSETS_NAME: assetsBucket.bucketName
  to both Lambda environment blocks. Also add to .env.test, setup.sh, bootstrap.sh,
  SAM template. When this merges, update ai/WORKTREES.md with a note unblocking
  backend-agent DEP-001.

IaC-002 (HIGH) — WAF CloudWatch log group naming violation
  AWS requires the log group name to begin with 'aws-waf-logs-'. Fix:
  logGroupName: `aws-waf-logs-costscrunch-${stage}`

IaC-006 (HIGH) — Missing API Gateway routes
  Cross-reference the README API table against CDK route definitions. Common gaps:
  GET /expenses/export (added with IaC-001), POST /groups/:id/join,
  DELETE /groups/:id/members/:userId, GET /analytics/chart-data, DELETE /auth/account.
  Each route needs: correct Lambda integration + JWT authorizer.

After every change: cd infrastructure && npm run synth
After networking/SG changes (LocalStack required): cd infrastructure && npm test
Use the lock guard from localstack-agent §9 — do not call docker compose up -d directly.
Open a PR when all fixes pass synth. Update ai/WORKTREES.md row to 'pr open'.
```

## cicd · `feat/cicd/fix-security`

```
You are the cicd-agent for this worktree (feat/cicd/fix-security).

Start by reading these files:
1. .agent.md — your full domain context and issue list
2. .github/workflows/workflow.yml
3. .github/workflows/deploy.yml
4. .github/workflows/rollback.yml
5. infrastructure/stacks/GitHubActionsStack.ts

IMPORTANT: You can edit and commit workflow YAML. You cannot push to the remote.
After committing, flag the human to push and monitor the first GitHub Actions run.

Your 6 issues, security criticals first:

SEC-002 (CRITICAL) — Static AWS keys instead of OIDC
  CI uses AWS_ACCESS_KEY_ID_DEV / AWS_SECRET_ACCESS_KEY_DEV long-lived secrets.
  GitHubActionsStack.ts already defines the OIDC IAM roles — they just aren't wired up.
  Fix workflow.yml and deploy.yml:
    permissions:
      id-token: write
      contents: read
    - uses: aws-actions/configure-aws-credentials@<SHA>
      with:
        role-to-assume: ${{ vars.DEV_GITHUB_ROLE_ARN }}  (or STAGING_ / PROD_ per job)
        aws-region: us-east-1
  Remove static key secret references once OIDC steps are confirmed.

SEC-001 (CRITICAL) — All third-party Actions unpinned (mutable tags)
  Every uses: line references a tag like @v4 instead of an immutable commit SHA.
  Pin every action. Find SHAs:
    gh api repos/actions/checkout/git/refs/tags/v4 --jq '.object.sha'
  Format: uses: actions/checkout@<sha>  # v4.x.x
  Actions to pin across all three files: actions/checkout, actions/setup-node,
  actions/upload-artifact, actions/download-artifact, aws-actions/configure-aws-credentials,
  plus any Semgrep, Gitleaks, or other third-party scanners present.
  After pinning, update ai/references/REFERENCES.md with the SHA table.

BUG-001 (HIGH) — rollback.yml has no AWS credentials step
  The workflow calls aws cloudformation rollback-stack but no credential step precedes it.
  Fix: add OIDC credential configuration as the first step in the rollback job
  (use vars.PROD_GITHUB_ROLE_ARN — rollback only ever touches prod).

BUG-002 (HIGH) — rollback health check exits non-zero, skipping the rollback step
  Fix: add if: always() to the rollback execution step so it runs even when the
  health check step fails.

CON-CI-001 (MEDIUM) — concurrent deploys not prevented
  Fix in deploy.yml:
    concurrency:
      group: deploy-${{ github.ref }}
      cancel-in-progress: false

CON-CI-002 (MEDIUM) — parallel CI jobs share a single LocalStack state
  backend integration tests and infrastructure LocalStack tests run concurrently and
  write to the same DynamoDB tables, producing flaky cross-job noise.
  Fix: add needs: backend-test to the infra-test job to serialize them.

After every edit, YAML lint all three files:
  python3 -c "import yaml; yaml.safe_load(open('.github/workflows/workflow.yml'))" && echo OK
  python3 -c "import yaml; yaml.safe_load(open('.github/workflows/deploy.yml'))" && echo OK
  python3 -c "import yaml; yaml.safe_load(open('.github/workflows/rollback.yml'))" && echo OK

Commit when all three lint clean. Then flag the human to push and verify the first run
with: gh run list --workflow workflow.yml --limit 5
Update ai/WORKTREES.md row to 'pr open'.
```
