# Changelog — 2026-06-03

## Worktree Bootstrap — Shared Config Base, Env Split & Workflow Guide

Bootstrapped a git-worktree–compatible development setup so multiple feature branches can run simultaneously without port collisions or config drift. Every worktree now symlinks shared config from the root and auto-assigns unique dev-server ports.

### Shared TypeScript Base (`tsconfig.base.json`)
- **Gap**: Each package (`backend`, `frontend`, `infrastructure`, `shared`) duplicated the same `compilerOptions` (ES2022 target, strict mode, etc.).
- Extracted a single `tsconfig.base.json` at the repo root with shared compiler settings.
- Updated all four package `tsconfig.json` files to `"extends": "../tsconfig.base.json"`, removing the duplicated boilerplate.

### Environment Variable Architecture
- **`env.shared.template`** (committed): documents all shared env vars (AWS region, DynamoDB tables, S3 buckets, EventBridge, Cognito, Redis, Bedrock, etc.) — copy to `.env.shared` and fill in real values.
- **`worktree.env.template`** (committed): documents worktree-local vars (`VITE_APP_URL` / `VITE_API_URL`) with port ranges (Vite: 3000–3009, SAM: 3010–3099).
- **`.worktreeinclude`** (committed): file-allowlist for worktree creation — copies `.env.local` and `.cognito.env` into each worktree but ignores large artifacts.

### Syslink Hook (`.claude/hooks/syslink-configs.sh`)
- Automates worktree initialization after `/worktree create`:
  - Symlinks `tsconfig.base.json` from root → worktree
  - Generates `.env.dev` = `.env.shared` + auto-scanned port assignments
  - Logs `[syslink-configs] Initialized worktree: VITE=3xxx SAM=3xxx`
- Prevents port collisions across parallel worktrees.

### Investigation
- **`🔴 Bug 1`** — The hang: blocking stdin read (root cause)
- The committed version of the hook (HEAD 9144769) reads stdin unbounded:
- INPUT=$(cat)      # ← what's actually committed (confirmed via git -S)
- The [ -t 0 ] guard only detects an interactive TTY. Claude Code's WorktreeCreate hook is spawned with stdin attached to a pipe, not a TTY — so the guard fails, the else branch 
- runs, and cat blocks forever waiting for an EOF that Claude Code never sends. → non-responsive hang.

- Your working tree has an uncommitted edit to `INPUT=$(timeout 1s cat || echo "")`. That degrades better, but see Bug 2.
- **🟠 Bug 2** — The "fix" depends on timeout, which doesn't exist on host
- ls /usr/bin/timeout  →  No such file or directory
- host ships no `timeout` in its base system — it only exists at /opt/homebrew/bin/timeout (coreutils). GUI-launched apps like Claude Code run hooks with a restricted PATH 
- (/usr/bin:/bin:/usr/sbin:/sbin) that excludes /opt/homebrew/bin. So timeout → command not found. You got lucky: || echo "" makes it fail fast rather than hang — but the safety 
- net you think you have isn't actually firing.

- **🔴 Bug 3** — Self-referential symlink already corrupted your repo (destructive)
- When Strategies A/B fail, Strategy C falls back to the *main* worktree, so WORKTREE_DIR becomes ROOT_DIR itself. Then line 59 runs:
- ln -sf "$ROOT_DIR/tsconfig.base.json" "$ROOT_DIR/tsconfig.base.json"   # points to ITSELF
- Confirmed live — your root file is now broken:
- tsconfig.base.json -> /Users/.../costscrunch/tsconfig.base.json
- wc -l tsconfig.base.json → open: Too many levels of symbolic links (ELOOP)
- It also dropped a stray .env.dev -> .env.shared in your repo root. The original `tsconfig.base.json` content was overwritten by the self-link.

-  **Fix**: 1. Blocking stdin read: `INPUT=$(cat)` blocked forever because Claude Code attaches stdin as a pipe (not a TTY) and never sends EOF. The `[ -t 0 ]` guard only detects interactive terminals. Replaced with a bash-native `read -t 2` that cannot hang.
- 2. `timeout` dependency: the interim `timeout 1s cat` fix relied on a binary absent from the macOS base system and from Claude Code's restricted GUI PATH (only at /opt/homebrew/bin). Removed entirely.
- 3. Wrong contract: per the official docs, WorktreeCreate REPLACES git's built-in creation. The payload carries a `.name` slug (not `.path`), and the hook must CREATE the worktree and print its absolute path to stdout. The old script never created anything and parsed a nonexistent field.
- 4. stdout pollution: every diagnostic `echo` went to stdout, which Claude Code reads verbatim as the returned path. All logging now goes to stderr; stdout emits only the final path.
- 5. Self-symlink corruption: Strategy C fell back to the main worktree, so `ln -sf "$ROOT/tsconfig.base.json" "$WORKTREE/tsconfig.base.json"` pointed the file at itself (ELOOP), destroying its contents. Added an explicit guard that aborts if the target resolves to the repo root.
