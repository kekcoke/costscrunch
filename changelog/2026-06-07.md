# Changelog — 2026-06-07

## Infrastructure Phase 3 Refactor — IaC-025: Decompose CostsCrunchStack into L3 Constructs

Decomposed the 1443-line monolithic `CostsCrunchStack.ts` into ten focused CDK L3 Construct classes, leaving `CostsCrunchStack.ts` as a ~290-line thin orchestrator. Precursor to the CDK + LocalStack migration. Branch `resolve/phase-3`.

### IaC-025 — CostsCrunchStack decomposed into L3 Constructs (`infrastructure/stacks/constructs/`)

- **Gap**: `CostsCrunchStack.ts` was a 1443-line constructor that provisioned every AWS resource inline — DynamoDB, S3, VPC, Cognito, SQS/SNS/EventBridge, 14 Lambdas, HTTP + WebSocket APIs, WAF, CloudFront, CloudWatch alarms, and all IAM grants in one class. Onboarding, debugging, and planned LocalStack migration were all blocked on the inability to scope work to a single domain without reading the entire file.

- **Approach**: Nested L3 CDK Constructs within the same CloudFormation stack (not multi-stack). Avoids cross-stack CloudFormation exports, preserves a single synthesized template, and produces zero operational change to LocalStack-based dev/test workflows. Logical IDs change (construct path adds one component), which forces resource replacement on the first post-refactor deploy — acceptable for dev (`RemovalPolicy.DESTROY`); staging/prod require `cdk import` or a coordinated destroy-recreate window.

- **New files** (`infrastructure/stacks/constructs/`):

  | File | Responsibility |
  |------|---------------|
  | `ConfigConstruct.ts` | SSM parameters (BedrockModelId, ViteAppUrl) + Secrets Manager (NotificationSecret) |
  | `NetworkConstruct.ts` | VPC, subnet groups, S3/DynamoDB gateway endpoints, 5 interface endpoints, `lambdaSg`, `redisSg`, ElastiCache `CfnReplicationGroup` |
  | `DataConstruct.ts` | DynamoDB `TableV2` (MainTable + 3 GSIs, global replica for prod) + ConnTable |
  | `StorageConstruct.ts` | 5 S3 buckets: uploads, processed, receipts, assets, quarantine (`CfnBucket` for `expirationInSeconds`) |
  | `CognitoConstruct.ts` | UserPool (MFA, password policy, email aliases), UserPoolClient (SRP + PKCE), 5 CfnUserPoolGroups |
  | `MessagingConstruct.ts` | SQS queues + DLQs (scan, notifications FIFO, wsNotifier), SNS Textract topic + IAM role, EventBridge bus + archive |
  | `ComputeConstruct.ts` | Powertools layer, shared env (22 vars), `mkFn` helper, all 14 Lambda functions as `public readonly` |
  | `ApiConstruct.ts` | HTTP API v2 (CORS, Cognito JWT authorizer, all routes), WebSocket API (`$connect`/`$disconnect`), stage; exposes `wsCallbackUrl` |
  | `EdgeConstruct.ts` | WAFv2 `CfnWebACL` (5 rules, CLOUDFRONT scope, log group + redaction), CloudFront distribution (S3 + API origins, CORS headers policy) |
  | `ObservabilityConstruct.ts` | SNS alarmsTopic, 14 Lambda error-rate alarms (MathExpression), 14 duration P99 alarms, DynamoDB throttle alarm, Textract MetricFilter + pipeline alarm, 3 DLQ alarms |
  | `SecurityAspects.ts` | `EncryptionEnforcementAspect` (S3, CfnTable, CfnGlobalTable), MOCK_AUTH guard, sensitive env var detection (OWASP ASVS V13.1) |

- **`CostsCrunchStack.ts` rewritten as orchestrator**: instantiates all 10 constructs in dependency order, then wires all cross-construct IAM grants, S3 event sources, SNS→SQS→Lambda subscription, Cognito post-confirmation trigger, EventBridge rules, provisioned concurrency, security aspects, and `CfnOutput`s in one visible place.

- **Circular dependency resolutions**:
  - `authTriggerLambda ↔ UserPool`: both use ARN tokens (not construct references); orchestrator wires `cfnUserPool.lambdaConfig` and `addPermission` after both constructs are created.
  - `wsNotifierLambda / imagePreprocessLambda ↔ wsStage.callbackUrl`: CDK token deferred via `addEnvironment()` in the orchestrator after `ApiConstruct` is instantiated.

- **LocalStack impact**: none. Resource names, Lambda function names, and SAM template entry points are convention-driven (`costscrunch-dev-*`), not derived from CDK logical IDs. `setup.sh`, `bootstrap.sh`, `localstack-client.ts`, and all integration tests are unchanged.

- **Snapshot tests**: `CostsCrunchStack.test.ts.snap` and `GitHubActionsStack.test.ts.snap` regenerated to reflect new construct-path logical IDs (expected; logical ID prefix changes from `Stack/Resource` to `Stack/Construct/Resource`).

- **Verification**: `npm run build` (TypeScript) ✅ clean; `npm run synth` ✅ clean (pre-existing deprecation warnings only); `npm run test` 107 passing / 12 pre-existing failures (unchanged from before refactor).
